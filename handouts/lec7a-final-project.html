Project objective

Define one user, one Kafka path, and one result

  • One path: how does an event become a useful output?
  • One proof: how will you show that it works?

Scope

Your input may be batch replay, realtime, or hybrid

Batch input

Replay records

A file can enter Kafka record by record through a producer or replay script.

Realtime input

Process arrivals

A live API, webhook, poller, or producer continuously creates events.

Hybrid input

Seed and continue

Historical replay establishes context, then live updates continue the same contract.

A notebook that reads a full CSV and draws one chart is not enough. The project still needs a streaming-style event path.

Review

Hard requirement

The reviewer must be able to access or run the project

  • Platform neutral: cloud or laptop can work.
  • Reviewer access: full cloud access or a local minimum demo.
  • Evidence complete: code, data, resources, instructions, and output.

Review contract

Choose how the reviewer will verify the project

Project pathThe final submission must provide
Cloud coreFull reviewer access, code, resource inventory, configuration, setup, sample input/output, validation, cleanup; local reproduction is not required
External APICredential setup, rate-limit note, cached sample, deterministic replay
Non-cloud/localPinned dependencies, one run path, sample or replay data, output, validation
DashboardData path, service startup, access steps, expected view, fallback evidence
Do not make the reviewer guess hidden steps or depend on your personal account.
