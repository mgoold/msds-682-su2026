P0 comparison · Keep only the semantic traps

Four look-alikes are not interchangeable

QuestionksqlDBFlink SQL
What is a table?A keyed table backed by a Kafka topicA logical dynamic table; Cloud maps Kafka topics to tables
What is a change?A Kafka record updates the keyed resultAn internal row kind: +I / -U / +U / -D
How does GROUP BY update?Materialized keyed/upsert resultUpdating table; may upsert or retract, depending on key and sink
How is a join time-bounded?WITHIN plus graceEquality key plus rowtime bounds and watermarks
Do not overstate retractions: -U appears only when the changelog must retract an old value. An upsert-capable keyed sink may use +U without -U.

ksqlDB · 1 of 6 · Three core concepts

Three concepts unlock ksqlDB

A Kafka-native streaming SQL database and runtime built on Kafka Streams.

01 · ModelKafka topic → STREAM or TABLEHistory or current keyed value
→
02 · DeploySQL → persistent queryksqlDB generates a running Kafka Streams topology
→
03 · ReadPush changes or pull current stateEMIT CHANGES subscribes; pull reads now
Runtime nuance: ksqlDB has an engine/server runtime, but its physical query plan is a Kafka Streams application. It is not the same kind of general engine as Flink.

ksqlDB · 5 of 6 · Planned SQL shape

The SQL should expose the same evaluation formula

-- Sink topic: msds682.demo09.ksqldb-pricing-evaluations-avro.v1
CREATE STREAM evaluations_09a AS
SELECT q.run_id, q.trip_id, q.quote_id, q.model_version,
       100.0 * (q.fare_cents - o.actual_cost_cents)
             / o.actual_cost_cents AS realized_markup_pct,
       ABS(100.0 * (q.fare_cents - o.actual_cost_cents)
             / o.actual_cost_cents - q.target_markup_pct)
             AS absolute_markup_error_pp
FROM quotes_run q
JOIN outcomes_run o WITHIN 1 HOUR
  ON q.trip_id = o.trip_id
EMIT CHANGES;

SELECT model_version, COUNT(*) AS n,
       AVG(absolute_markup_error_pp) AS mae_pp
FROM evaluations_09a
GROUP BY model_version EMIT CHANGES;

Flink SQL · 1 of 6 · Four core concepts

A query turns one changing table into another

Flink SQL is the relational interface to Apache Flink’s distributed stateful engine.

01 · InputKafka eventsAppend-only inputs arrive as inserts
→
02 · ViewDynamic tableThe logical table changes over time
→
03 · QueryContinuous GROUP BYThe runtime maintains state
→
04 · ResultUpdating dynamic tableThe result changes as facts arrive
+I insert-U retract old+U update new-D delete Possible row kinds, not fields added to every Kafka event
Two orthogonal owners remain: watermarks advance event time; checkpoints recover managed state. SQL does not remove either responsibility.

Official sources: dynamic tables and changelogs · event time and watermarks · checkpoints versus savepoints.

Flink SQL · 4 of 6 · Planned Demo 09B

Filter one run, then use an interval join

WITH quotes_run AS (
  SELECT * FROM `msds682.demo07.ml-fare-quotes-avro.v1`
  WHERE run_id = 'model-compare'
), outcomes_run AS (
  SELECT * FROM `msds682.demo07.ml-trip-outcomes-avro.v1`
  WHERE run_id = 'model-compare'
)
SELECT q.run_id, q.trip_id, q.quote_id, q.model_version,
       100.0 * (q.fare_cents - o.actual_cost_cents)
             / o.actual_cost_cents AS realized_markup_pct
FROM quotes_run q
JOIN outcomes_run o
  ON q.trip_id = o.trip_id
 AND q.$rowtime BETWEEN o.$rowtime - INTERVAL '1' HOUR
                    AND o.$rowtime + INTERVAL '1' HOUR;
